# Collaboration Plans

Store concise, repository-local implementation contracts here when another agent must resume or integrate the work. Plans support execution; completion still requires runtime gates and evidence.

Use filenames of the form `TD-###-short-topic.md`. Every plan must include:

- goal, player-facing or operational outcome, and explicit non-goals;
- pinned base SHA, branch, owner, exclusive files, and forbidden files;
- observable dependency contracts rather than promised line numbers;
- file-level deliverables and an ordered implementation sequence;
- falsifiable acceptance criteria and named verification evidence;
- trim order, never-cut items, assumptions, and numbered deviation candidates;
- handoff and integration responsibilities.

For gameplay plans, design exactness tests on paper before code and pin the tick-observation convention next to the arithmetic. Run plan preflight against the MGS reviewer checklist before implementation.
